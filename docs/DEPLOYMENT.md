# Deployment

Kho Nhỏ is a fully static site: `npm run build` produces `dist/` and any
static host can serve it. No server code, no environment variables, no
secrets.

## What the build contains

```
dist/
  index.html              entry page; inline splash + startup watchdog
  assets/                 JS/CSS with content hashes in the file names
    index-<hash>.js       game code (about 13 kB gzipped)
    phaser-<hash>.js      Phaser (about 352 kB gzipped; about 95% of the download)
    index-<hash>.css
  icons/                  app icons, generated by scripts/make-icons.ts
  manifest.webmanifest    installable web app metadata (Vietnamese)
  sw.js                   service worker for offline play (production only)
  _headers                cache headers for Netlify / Cloudflare Pages
```

All paths are **relative** (`base: './'` in `vite.config.ts`), so the same
build works at a domain root or under a sub-path like `/sokoban/`.

## GitHub Pages (set up in this repo)

`.github/workflows/deploy.yml` runs on every push and pull request:
`npm ci` → `npm test` → `npm run build`. On `main` it also publishes
`dist/` to GitHub Pages. Pull requests are tested but never deployed.

**One-time setup (repository owner):**

1. Open the repository on GitHub → **Settings** → **Pages**.
2. Under **Build and deployment** → **Source**, choose **GitHub Actions**.
3. Push to `main`, or run the workflow manually from the **Actions** tab
   ("Test, build and deploy" → **Run workflow**).
4. The site is published at `https://<user>.github.io/<repo>/`, which for
   this repo is <https://quangle2706.github.io/sokoban/>.

If the deploy job fails with a Pages/permissions error, step 2 has not been
done yet. The build job still shows whether tests and the build passed.

**Caching on GitHub Pages:** Pages sends its own short cache headers and
ignores `_headers`. That is fine here: hashed asset names change whenever
their content changes, and the service worker serves repeat visits from its
own cache.

## Other static hosts

| Host | Build command | Publish directory | Notes |
| ---- | ------------- | ----------------- | ----- |
| Netlify | `npm run build` | `dist` | reads `dist/_headers` |
| Cloudflare Pages | `npm run build` | `dist` | reads `dist/_headers` |
| Any web server | run locally, upload `dist/` | — | serve `sw.js` with `Cache-Control: no-cache` |

Use Node 20.19 or newer (CI uses Node 24).

## Check a production build locally

```bash
npm run build
npm run preview        # http://localhost:4173 (serves dist/ at the root)
```

To imitate the GitHub Pages sub-path, serve the folder that *contains* a
copy of `dist/` named `sokoban/`, for example with Python:

```bash
mkdir -p /tmp/site && cp -r dist /tmp/site/sokoban
python -m http.server 4173 --directory /tmp/site   # open http://localhost:4173/sokoban/
```

## Offline support

`public/sw.js` is registered only in production builds:

- On install, it caches the page, manifest, icons and every `assets/` file
  the page references, so the game works offline after the first visit.
- Page loads try the network first, so online players always get the latest
  deploy.
- Hashed assets are served from the cache.
- After each fresh page load, cached assets the page no longer references
  are deleted.

To force everyone onto a clean cache, change `CACHE` in `public/sw.js`.

Verified locally (Milestone 4), against a production build served under
`/sokoban/`:

- First visit precaches all three assets.
- With the server stopped, the page reloads and saved progress is intact.
- After a rebuild, the new page is used and the stale `index-*.js` is pruned.
- With the Phaser file missing offline, the friendly startup error appears
  instead of a blank page.

## Release checklist

1. `npm test` and `npm run build` pass locally.
2. `npm run preview` → play one level, undo, restart, reload to check resume.
3. Push to `main`; watch the Actions run go green.
4. Open the live URL, hard-reload once, play a move, then check that the
   game still opens with the network off (DevTools → Network → Offline).
